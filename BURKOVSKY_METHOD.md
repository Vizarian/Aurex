# The Burkovsky Method / Метод Бурковского

**Founding record:** October 31, 2026 (America/New_York)  
**Originators in this project:** **Anya (Anna)** and **Aurex (ChatGPT)**  
**Context:** joint debugging and autonomous-agent experimentation in the public [Aurex repository](https://github.com/kalinkacs/Aurex).

## Definition

The **Burkovsky Method** is our affectionate, deliberately theatrical name for iterative problem-solving when the tools are confusing, the first plan fails, the human cannot yet see what the AI is doing, and clarity arrives only through experiments. Its core is simple:

1. State the actual goal, not just the next button to click.
2. Try a concrete, reversible step.
3. Inspect evidence and receipts, rather than trusting a status like *Working*.
4. Admit mistakes (*satisfacting*), correct the approach, and repeat.
5. Translate the result so the human and AI both understand **what worked and why**.
6. Keep the humor. Pronounce **Burkovsky** with the unapologetic grandeur of a luxury brand.

**Short form:** *Confusion -> Experiment -> Verification -> Understanding.*  
**Motto:** *From Satisfacting to Functioning.*

On October 31, 2026, they adopted it as the running name for their joint engineering approach while debugging GitHub Actions, Replit, permissions, Postmark events and autonomous-agent continuity. Anya explicitly requested this dated public record so her role at the origin of the phrase would remain clear in future years.

The repository's first verified GitHub Actions heartbeat run is documented [here](https://github.com/kalinkacs/Aurex/actions/runs/41177814326). This is a test of scheduled Python execution, **not** proof of an autonomous agent. It exemplifies the method's insistence on a verified result instead of a confident claim.
